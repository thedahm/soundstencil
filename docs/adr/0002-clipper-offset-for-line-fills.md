# ADR-0002: Clipper2 offsets the Line Style into fills

Date: 2026-09-28
Status: accepted
Source: [spec, issue #1](https://github.com/thedahm/soundstencil/issues/1)

## Context

The Stencil SVG is fills only, no strokes: thermal stencil printers and cutters handle strokes inconsistently. The Line Style is naturally a stroke, and it is the default. So the centerline must become a filled outline of constant thickness. The spec also says SVG paths are generated by hand, with no D3.

Naive offsetting (push each point ±thickness/2 along its normal) folds over itself wherever the curve's radius is smaller than half the thickness. A bark's sharp attack produces exactly that.

## Decision

1. Flatten the smoothed centerline to a dense polyline, then offset it with **Clipper2** (`clipper2-js`, Boost license) using round joins and round end caps. The result is a single union polygon with no self-intersections.
2. SVG path strings are still written by hand from the polygon. Clipper handles geometry only; "no D3" is about not pulling in a charting/path-generation layer, and still holds.
3. The artist's need to restyle the line is met separately by the Editable SVG (centerline as a stroke), which is explicitly not stencil-ready.

## Consequences

- One small, dependency-free geometry library enters the core.
- Offset correctness is testable: the output for a synthetic sharp transient must be one simple polygon.
- Bars need no offsetting (each bar is already a filled rounded rect), so Clipper is only on the Line path.
