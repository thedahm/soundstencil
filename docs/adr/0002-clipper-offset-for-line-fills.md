# ADR-0002: Clipper2 offsets the Line Style into fills

Date: 2026-09-28
Status: accepted
Source: [spec, issue #1](https://github.com/thedahm/soundstencil/issues/1)

## Context

The Stencil SVG is fills only, no strokes: thermal stencil printers and cutters handle strokes inconsistently. The Line Style is naturally a stroke, and it is the default. So the centerline must become a filled outline of constant thickness. The spec also says SVG paths are generated by hand, with no D3.

Naive offsetting (push each point ±thickness/2 along its normal) folds over itself wherever the curve's radius is smaller than half the thickness. A bark's sharp attack produces exactly that.

## Decision

1. Flatten the smoothed centerline to a dense polyline, then offset it with **Clipper2** (`clipper2-js`, Boost license) using round joins and round end caps. The result is a single union polygon with no self-intersections.
2. SVG path strings are still written by hand from the polygon. Clipper handles geometry only; "no D3" is about not pulling in a charting/path-generation layer, and still holds.
3. The artist's need to restyle the line is met separately by the Editable SVG (centerline as a stroke), which is explicitly not stencil-ready.

## Consequences

- One small geometry library enters the core.
- Offset correctness is testable: the output for a synthetic sharp transient must be one simple polygon.
- Bars need no offsetting (each bar is already a filled rounded rect), so Clipper is only on the Line path.

## Amendment (2026-09-28, issue #6)

- `clipper2-js` 1.2.4 is not quite dependency-free. It depends on `tslib`, which the bundle never imports. It also declares Angular 15 as a peer, though no code uses it. `.npmrc` sets `legacy-peer-deps=true` so npm doesn't install Angular, rxjs and zone.js alongside it. The built bundle has no imports.
- This port's whole-polyline open offset gets sharp concave turns wrong. It winds part of the stroke negatively, and its Positive-fill union then drops that part. The result is holes inside the stroke, or an outline split at every spike. So each polyline segment is offset on its own as a round-capped capsule, and Clipper unions them. The shape is the same: every point within half the thickness of the line, which is what round joins with round caps give. The only cost is speed, about 100 ms at the defaults. The UI redraws the preview at most once a frame.
- Its `executePolytree` swallows an internal error and returns nothing, so the code uses `execute`.

## Amendment (2026-09-28, issue #7)

- The port's closed-polygon offset is broken too: every join type drops corners and comes out short, even for a plain square. Rebuilding erosion and dilation from edge capsules works but takes seconds on a Line outline. So Thin Spot detection doesn't use Clipper: it rasterizes the ink (at most 400k cells, about 0.075 mm at the default Print Size) and opens and closes it with exact distance transforms, in tens of milliseconds.
